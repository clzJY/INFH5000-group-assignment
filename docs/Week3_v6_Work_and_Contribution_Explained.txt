Week3 v6：我们做了什么、提了什么、和谁比？
2026-11-11

1. 已经完成的小改动
本轮研究的核心是“沿既定路线进行风险预测，再选择速度”的小模块，对应表里的 Forecast: measured velocity。它读取同一条参考路线、机器人状态、行人位置与推算速度；在未来1.5秒内分别尝试正常前进、减速、停车，检查机器人和行人的身体轮廓是否可能同时占据相同位置，然后给底层跟踪器一个速度选择。它改变行进速度，不重新规划一条全局路线。当前轮椅形轮式机器人在MetaUrban原生三维环境里运动，没有训练新神经网络，也没有依靠摄像头识别人。

2. 我们已经完成的研究工作
围绕上述模块，搭建共享输入的比较框架，实现各个本地对照版本，完成68次开发运行，以及120次主测试、40次单行人诊断测试；保存轨迹、原生碰撞标记、视频、严格到达和无接触到达等结果。空间图来自实际记录。报告的研究贡献包括这个可检查的小型实现、配对实验及失败分析。方法思想来自现有研究，本作业不声称发明了行人预测或取得SOTA。

3. 六个方法的身份
Forecast: measured velocity：我们实际实现并研究的核心模块。沿路线预测身体占用，用测得的行人速度选择机器人速度。
PP + static guard：简单基线。使用Pure Pursuit路线跟踪，加共同的静态保护。
RPP-inspired：基线。参考Regulated Pure Pursuit思想，调节曲线和邻近障碍处的速度；是我们的本地适配版本。
DWA-style：基线。参考Dynamic Window Approach思想，尝试局部速度和转向；同样是本地适配版本。
Distance yield：简单对照。只用当前位置的行人间距减速，检查“仅看距离是否已足够”。
Forecast: zero velocity：消融对照。和核心模块采用同一预测/候选选择过程，仅把预测中的行人速度设为0；实际行人仍在运动。它检查速度信息本身有没有贡献。
ORCA：仿真人群运动生成机制；不是本次表格中的额外机器人比较方法。
这些版本的代码均由本项目在AI辅助下实现/适配；“基线/对照”描述实验中的身份，不是说那些代码没有由我们执行。

4. 目前得到什么结论
核心模块与零速度消融都得到16/20严格到达、13/20无接触到达；因此，本样本没有证明速度信息本身改善这些总体计数。核心模块在与RPP共同成功的16个条件里平均快3.16秒，但比零速度消融慢0.28秒，不能把对RPP的时间差全归因于行人速度预测。
五个沿路线跟踪的方法在相同四个条件持续停滞，DWA-style能完成这四个条件，但也在另外六个预测模块可完成的条件中失败。我们因此获得一个具体研究动机：某些问题是空间路线受限，仅调速度可能解决不了。这是有价值的诊断发现，并不证明真实通道一定不可通行。

5. 我们进一步提出什么
后续提案是“持续静态受阻时才启动的有限局部绕行触发器”。平时继续使用现有预测模块；当静态检查导致持续等待时，尝试有限范围内的左右临时航点。候选必须位于经验证可行走区域，并保留身体间隔要求；没有合格候选就继续等待。这个模块目前没有实现，也没有效果数据。

6. 后续实验与我们的关系
这120次是专门用来验证我们上述扩展的未来实验，不是引用别人的实验，也不是已完成160次中的一部分。三组是：①RPP-inspired基线；②现有预测模块；③现有预测模块＋新绕行触发器。第③组是新提案，第②组帮助判断增加触发器带来的变化，第①组提供已有方法参照。10个新场景编号×2类经验证布局×2种人数×3组=120次。先用独立开发场景确定触发与偏移设置，再冻结测试、保留全部失败。预期检验的是严格到达能否提高，同时不减少无接触到达；现在没有保证会改善。
