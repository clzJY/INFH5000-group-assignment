# 经典方法与这一轮小改动的关系

这轮工作的目标是做一个能讲清楚、能复现的小研究。我们不以达到 SOTA 为要求，也不将已有的经典思想包装成新算法。旧版 proposal 全部保留，新增 v3，GenAI 附录继续由你后续处理。

## 先区分 PP 和 PPO

**PP（Pure Pursuit，纯跟踪）** 是几何控制：沿路线找一个前方目标点，计算该向左还是向右转。它不需要训练。可以把它理解为“先沿着给定道路走稳”。本轮六个方案都共用这一条路线和同一套基本接口。

**PPO（Proximal Policy Optimization）** 是训练策略网络的一种算法。拿一个 PPO checkpoint 测试，测到的是这个网络在当前输入、任务和动作接口下的表现。旧版预训练策略的表现不能代表所有强化学习方法，也不能作为新风险模块优于经典导航技术的充分证据。因此旧实验保留为路线/到达判定的审查，新实验采用共享信息的经典方案。

## 相关论文解决了什么，我们实际实现了什么

| 文献/技术 | 原有思路 | 本轮的位置和限制 |
|---|---|---|
| [Coulter, 1992：Pure Pursuit](https://publications.ri.cmu.edu/implementation-of-the-pure-pursuit-path-tracking-algorithm) | 用前方参考点控制路径跟踪 | 所有方案共用的路线骨架；PP 本身不等于行人避障 |
| [Macenski 等, 2023：Regulated Pure Pursuit](https://arxiv.org/abs/2305.20026) | 在跟踪路径时依据弯曲程度、障碍接近等信息调节速度，并做碰撞投影检查 | 实现 RPP-inspired：曲率/接近调速、当前行人占据下的短时投影；没有复现 ROS costmap 和完整 Nav2 插件 |
| [Fox 等, 1997：Dynamic Window Approach](https://publications.ri.cmu.edu/the-dynamic-window-approach-to-collision-avoidance) | 在动力学允许的速度窗口内搜索局部运动，平衡前进、避障等目标 | 实现 DWA-style：原生四轮接口下搜索速度和转角，使用相同状态/碰撞盒；不是原论文同步驱动机器人算法的完整复现 |
| [van den Berg 等, 2011：ORCA](https://gamma.cs.unc.edu/ORCA/) | 在互相承担避让责任的假设下选择速度 | 原生行人路径生成背景。此处行人预规划/脚本运动不能证明对机器人做了互惠避让，所以不宣称 ORCA 的理论保证适用于本场景 |
| [Ohnishi、Takahashi, 2026：Dynamic Window Pure Pursuit](https://arxiv.org/abs/2601.15006) | 将动态窗口思想与路径跟踪、运动约束结合 | 可作为后续更成熟的约束跟踪参考；本轮没有把 DWPP 实现或成绩算进比较 |
| [Wu 等：MetaUrban](https://arxiv.org/abs/2407.08725) | 三维城市微出行/社会导航仿真平台 | 提供原生道路、街景物体、行人和物理；我们的数字只对应 tiny 资产和当前任务协议 |
| [Francis 等, 2023：社会导航评估原则](https://arxiv.org/abs/2306.16740) | 区分安全、舒适、可理解性、情境等多种要求，强调可重复的评估 | 到达、接触、近距离暴露、等待分别报告；几何距离不能直接代替人的舒适感 |

这些文献说明，调速、短时预测、轨迹搜索都有成熟研究。本轮的价值在于把一个很小的路线条件预测模块放进真实三维街景，在相同输入下做可审查的对照、消融和失败分析。它不支持“首次解决行人导航”之类的结论。

## 路线修正解决什么

旧网络有时停在不合适的位置，或者方向和完整参考路线不一致。路线修正负责“该往哪里走、怎样朝着终点继续前进”。它使用了完整路线，旧的 PPO 输入并没有同样的信息，因此旧版从 3/20 到 18/20 的严格到达提升不能全部算给风险预测。

本轮直接采用共同的纯跟踪骨架，不再依靠神经策略输出。这样各方案在“知道路线、基本能够跟踪”这一点上保持一致，比较更容易解释。

## 新风险模块解决什么

风险模块负责“按照这条路线前进时，现在选什么速度比较合适”。它逐一尝试正常速度、减速、很慢地走和停车，向前推演 1.5 秒：

1. 机器人按给定路线转弯，并受到加速/制动限制。
2. 行人按最近测到的速度短时继续移动。
3. 使用机器人和行人的实际平面碰撞盒比较间距，避免只看中心点或一个粗半径。
4. 选择通过几何 buffer 检查的最高候选速度。如果没有候选通过，就明确记录“无满足 buffer 的候选”，而不是宣称停车必然安全。

举例：前方有人正在远离，单看距离可能让机器人不必要地慢下来；加入速度后可能允许继续。有人即将横穿，则可以提前调整到达交汇点的时间。有人一直迎面走向已经停住的机器人，单靠停车仍可能接触。固定障碍挡在路线上时，速度控制也可能一直等待，因为它没有规划一条绕行路线。

这套推演使用近似的运动模型和理想状态，有限制动也需要时间；它是可检验的控制启发式，不是安全证明。

## 为什么增加这些对照

- PP + 公共静态物体保护：检验稳妥的基本路线控制已经能做多少。
- RPP-inspired：检验成熟的调速/当前占据投影思路，避免只比较较弱的旧网络。
- Distance：只看当前间距，作为简单风险控制。
- Forecast-static：保留完整预测过程，只把行人速度设为零。
- Forecast：与上一项逐项相同，只增加测得的行人速度；这是一项直接的消融。
- DWA-style：除了速度，也搜索局部转角，用于检验增加横向选择是否有价值。

我们还把随机 5/15 人街景与单行人受控场景分开：前者看整体任务结果，后者解释横穿、远离、迎面和静止分别怎样影响策略。受控行人的运动是人为规定的，不能冒充自然人的交互行为。正式结果和对作业的意义见同目录的 `classical_review_20261102.md`。
